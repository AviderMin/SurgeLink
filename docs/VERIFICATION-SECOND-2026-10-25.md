# 1.0.2.41 二次审查修复验证

基线：`3b2d9b9`，2026-10-25。本轮修改保留在工作区，未提交、推送或重新打包；已有 1.0.2.41 安装包不包含这些修改。

## SCP 文件身份

移除按行拆分 `ls` 的列举和 Stat 实现。服务端改为生成 NUL 分隔记录，路径及链接目标以原始字节的十六进制表示传输，元数据包含完整 Unix 时间戳及模式位，并带协议头和结束标记。

客户端验证完整响应、记录字段、文件类型、精确路径、直属子项关系、重复身份和 UTF-8 编码。任一记录无效时整次调用失败，不返回部分列表，不回退到 `ls`。Stat 必须收到且仅收到所请求路径的记录。主目录也使用编码协议，避免裁掉合法路径末尾的换行。

真实 Git Bash/GNU 工具测试创建了含换行及伪造权限行的文件，同时创建真实 `victim` 文件：

- List 返回一个完整的攻击文件身份及真实的其他文件，没有伪造 `/ghost` 条目。
- Stat 返回完整请求路径；实际 `victim` 内容仍为 `keep`。
- 单引号、制表符、中文及末尾换行的实际文件名也保留完整身份。
- 协议单元测试覆盖空目录、根目录、特殊权限、UTC 秒时间戳、带箭头/换行的链接目标、非法元数据、非法 UTF-8、NUL、重复记录、截断响应和非直属子项。
- 不兼容的 `stat` 调用失败，残缺响应被拒绝。

兼容条件：需要 POSIX `sh`、支持 `stat -c '%f %s %Y %u %g'` 的工具、`od`、`tr`，符号链接需要 `readlink -n`。参数与 GNU/BusyBox 格式相容，BusyBox 参数说明见[官方命令文档](https://busybox.net/BusyBox.html)；本轮实际 shell 测试使用 GNU 工具，没有实际 BusyBox 服务端验收。不兼容的 BSD/stat 实现不会降级到不安全的列表解析。路径和链接目标须能无损表示为 UTF-8；所有者显示数值 UID/GID。

## 监控通知与节流

锁内只选择并保留待通知订阅、处理一次性订阅和更新调度；用户通知在锁外执行。待通知订阅若已退订则不调用，已领取的在途回调允许完成。回调异常不影响剩余通知；一次性回调中注册下一次订阅也能正常完成。

协议取消钩子也属于外部回调，因此取消移到调度锁外异步执行。单调时钟负责计时，采样、可选进程查询及通知结束后再等待配置间隔，不追赶漏掉的周期。

原锁复现程序中，慢回调阻塞 3 秒时，新订阅注册耗时约 1 毫秒。回归测试还验证退订不阻塞、退订抑制待通知回调、一次性订阅重入、通知异常、协议取消钩子及慢快照/进程查询后的完整间隔。

### 对第 3 项报告的核实

给出的“1.2 秒采样、1 秒间隔、8.5 秒内调用 4 次”本身符合完成后节流，并不足以证明连续轮询。对基线补充实际时间戳后，每次采样完成到下一次开始间隔为 1001、1008、1007 毫秒，共 4 次调用，没有复现取消间隔的现象。

本轮仍明确强化了完成后的调度：通知也纳入完成边界，使用单调时钟，并补充混合订阅及慢进程查询的回归测试。修复后同一时间戳程序的间隔为 1016、1000、1000 毫秒，仍为 4 次调用。
