# 实际使用流程审查与修复验证（2026-10-27）

本轮基线为 `6eceaa4`。审查重点是连接初始化、终端窗口尺寸同步、远程文件操作、传输队列与断线关闭的交叉流程。本文件记录本轮工作，不替代其他日期或其他基线的审查报告。

## 修复内容

| 用户场景 | 原来的问题 | 修复后的行为 |
| --- | --- | --- |
| 调整窗口、切换视图造成连续布局通知 | 与本地尺寸相同的通知会提前退出，却增加了请求编号，导致此前排队的最终远端尺寸被判为过期；取消或失败后用相同尺寸重试也会提前退出 | 单独记录远端成功接收的尺寸；重复通知继续承担未完成的同步，成功后才去重，取消或失败后允许重试 |
| 已成功连接，但主机信息尚未读取完成时断线 | 状态事件通过已发布标签列表查找目标；此时标签尚未加入列表，事件被丢弃，随后仍显示已连接并接受传输 | 状态事件直接绑定正在创建的标签；初始化期间同样保留断线状态和错误信息，并关闭传输队列；之后的 Shell 关闭通知不再覆盖连接错误 |
| 断线触发传输清理后，用户立即关闭标签页 | 第二次 `DisposeAsync` 直接返回，关闭流程可能在第一轮传输清理尚未完成时就释放协议连接 | 所有关闭调用共享同一个完成任务，遵守原有 10 秒清理等待上限；取消和通知在队列锁外执行 |
| 文件夹排队下载期间，源目录或子项被替换 | ZIP 下载只信任早先的目录元数据，未像单文件下载一样在读取前重新核对类型 | 在遍历每个目录前确认仍为目录，在读取每个文件前确认仍为普通文件；失败时移除临时 ZIP，不发布部分下载 |
| 上传结束后查看当前文件列表 | 完成事件只显示提示，文件列表仍是上传前的结果 | 上传完成、失败或取消后刷新当前目录，让成功提交的文件和部分完成的子项可见；刷新请求支持传输工作线程 |
| 新建、重命名或粘贴尚未结束时，继续进入别的目录 | 异步操作完成后的刷新使用启动操作时捕获的路径，可能把用户带回之前的目录 | 刷新读取最新的导航请求，不再使用旧回调捕获的路径 |

## 回归验证

新增 12 个回归用例，覆盖：

- 重复终端布局通知不能丢失排队的最终尺寸。
- 调整尺寸在排队或发送阶段取消后，均能以相同尺寸重试。
- 远端尺寸更新失败后能以相同尺寸重试。
- 两个关闭调用都等待正在执行的传输完成取消清理。
- ZIP 根目录、嵌套目录、普通文件分别被符号链接替换，以及文件变为特殊文件时，拒绝继续遍历或读取（4 个用例）。
- 初始化期间进入 Disconnected / Faulted 状态时，保留状态和诊断并拒绝传输（2 个用例）。
- 断线后的 Shell 关闭不覆盖网络错误。

其中前期加入的 8 个传输/尺寸用例、2 个初始化断线用例，均先在修复前运行失败，再验证修复后通过。另补充尺寸失败重试与 Shell 关闭后的错误保留用例。

## 界面与验证边界

使用本次源码的 Release x64 可执行文件，在 Windows 桌面进行离线 Demo 冒烟检查：连接已有演示会话、进入文件页、进入 Documents 子目录、刷新保持当前目录、切换监控并确认指标出现、返回文件页保留目录。检查后正常退出测试应用。

上传完成后的自动刷新、异步操作完成时导航不回退，已核对调用链并通过应用编译；本轮没有用真实 SSH 服务器或限速上传进行端到端复现。初始化断线、传输并发清理和文件类型变化由可控协议/文件系统替身确定性验证。未进行真实串口硬件、ARM64 或 Windows 10 实机验收。

文件类型复查属于操作前检查，远端的 Stat 与 Open/List 不是原子操作；不保证消除其他进程恰好在两次远端请求之间替换路径的所有竞态。队列仍保留既有的有界关闭等待策略。
