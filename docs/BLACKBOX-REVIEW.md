# SurgeLink 黑盒测试审查

审查日期：2026-10-21。范围：当前仓库、1.0.2 发布 ZIP、应用 UI 流程与现有测试工具。目标是设计可重复的外部行为验证；不是安全渗透审计，也不把静态阅读等同于实际功能通过。

## 审查发现

| 优先级 | 证据 | 风险与本次处理 |
|---|---|---|
| P0 | 之前 0.1.0.0 安装包缺少合并资源索引，结构签名检查通过仍无法启动；`tools/package-appx.ps1` 现已合并 PRI | 安装包结构检查不能替代部署后启动。新增 PKG007 防缺失回归；M01-001/002 要求从开始菜单激活并检查升级数据。桌面 EXE 冒烟不冒充 AUMID 安装激活验证。 |
| P1 | `tools/verify-app.ps1` 的 Set-Language 直接覆盖真实 `%LOCALAPPDATA%/SurgeLink/settings.json`，同时启动 Demo、创建文件；finally 仅恢复 settings | 共享配置下并发运行可能覆盖用户运行期间的新偏好；Demo 操作可能持久化测试会话。新增 UI runner 不写 settings，不使用 Demo，不接管现有进程；仍要求专用账号/VM。 |

## 范围与用例设计

采用等价类、边界值、状态迁移、场景组合和错误推测。覆盖安装/升级/证书、会话、SSH认证与主机密钥、终端、文件、传输、远程编辑器、监控、设置与本地化、无障碍、可靠性与数据保护。

端口重点：空值（默认）、1、65535 为有效类；0、-1、65536、abc、22.5 为无效类。传输重点：零字节、缓冲区邻接值、二进制与大文件。主题与语言覆盖保存/取消/重启；网络覆盖认证失败、拒绝、超时、断网、恢复；远程操作必须核对实际文件 SHA256 与受控服务端状态。

测试清单：[BLACKBOX-CASES.md](BLACKBOX-CASES.md)。运行说明：[tests/blackbox/README.md](../tests/blackbox/README.md)。

## 自动化边界

- Package：18 项，基于发布 ZIP、APPX 清单、可观察文件、CMS证书关系及安装脚本退出码；负向测试只改工作副本。
- Desktop：25 项，基于独立测试进程的 UI Automation；覆盖启动、设置/关于、空主机和端口无效类、筛选和关闭。提供脚本但本次未在专用测试账号运行。
- Manual：104 项；包括需要管理员/VM/SSH/网络故障/屏幕阅读器的操作。这些状态保持 NotRun。
- 黑盒 UI 自动化不解析私有状态、不调用内部类；文件/参数代码阅读仅用于识别需求和测试入口。
- 不会自动运行旧 verify-app.ps1，也不自动修改系统设置、凭据、证书或生产远端文件。

## 验证与验收

本次现有1.0.2 ZIP 的 Package 套件：18/18 通过，失败0、跳过0。报告生成 JSON、CSV、HTML 和 JUnit；全量 coverage.csv 明确其余129项未执行。

这不是147项全通过，也不是完整发行验收。建议发布门槛：P0不得失败；所有自动化在目标环境通过；安装启动/升级、真实SSH认证、文件完整性、SCP回退和关键数据保护P0场景必须有实际证据；跳过项说明原因并由测试负责人确认。

手工实际结果应至少记录：用例ID、版本、环境、输入、预期、实际、状态、执行人、时间、证据路径和缺陷ID。对UI字体、对比度、缩放等，不使用“文本节点存在”替代真实视觉或辅助功能验证。
