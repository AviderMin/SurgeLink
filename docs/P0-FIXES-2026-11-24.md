## 4. 安装包体积

`tools/package-exe.ps1`、`tools/package-appx.ps1` 原先把自包含的 CLI 和 MCP Host
分别发布到 `cli/` 与 `agent/`，于是安装包里出现**三份逐字节相同的 .NET 10 运行时**
（CLI 与 AgentHost 的 192 个同名文件哈希完全一致）。

现在两者先发布到临时目录，再与桌面程序**合并到同一安装目录**，共用桌面那份运行时。
合并时逐文件比对 SHA256：同名但内容不同即判定为真实冲突并报错，不会静默覆盖。
`AgentWorkspaceService.LocateExecutable` 优先在应用根目录查找，旧布局的 `cli/`、
`agent/` 仍作为回退。

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 安装包 | 113.11 MB | **64.31 MB** |
| 展开后 | ~384 MB | **234.2 MB**（561 个文件） |
| 安装目录结构 | `SurgeLink.exe` + `cli/` + `agent/` | 三个 exe 同级 |

已实测：静默安装到临时目录后，`surgelink-cli.exe --help`、`surgelink-agent-host.exe --help`、
桌面程序（含打开演示会话）均正常；Agent 面板诊断输出
`MCP host: <安装目录>\surgelink-agent-host.exe`、`MCP host exists: True`。

## 5. 中文输入法：实测否决

按设计应通过 `CoreTextServicesManager.GetForCurrentView()` + `CoreTextEditContext`
接管组词。**实测结论：在 WinUI 3 桌面窗口中不可用。**

- 仅创建 edit context：稳定。
- 调用一次 `NotifyFocusEnter()`：**3/4 次启动在打开会话后数秒内 fail-fast 崩溃**
  （`0xc0000409`，`BEX64`，Windows 事件日志 Application 1000/1001）。
- 崩溃与具体事件处理器无关：`TextUpdating`/`SelectionUpdating` 处理器在场时同样崩溃，
  去掉全部处理器仍然崩溃；完全去掉 `NotifyFocusEnter` 则稳定。
- 与微软文档一致：`CoreTextServicesManager` 在 WinUI 3 中「仅 Windows 11 支持」，
  且依赖 `CoreWindow`——而 `CoreWindow` 在 WinUI 3 桌面应用中不受支持
  （<https://learn.microsoft.com/windows/apps/windows-app-sdk/migrate-to-windows-app-sdk/what-is-supported>）。

因此本项**未合入**：已回退全部 `CoreTextEditContext` 代码（含 `TerminalImeBuffer` 及其测试），
保留原有的 IMM32 候选窗口定位（`TerminalSurface.Cursor.cs`，只做定位、不接管输入）。
回退后连续 3/3 次启动稳定。

**仍需处理**：中文/日文/韩文组词目前只能退化为逐字输入。可行方向是改用
TSF（`ITfThreadMgr` + 自绘 `ITfContext`）或嵌入一个隐藏的 `RichEditBox` 承担组词，
二者都需要真机 IME 验证，建议单独立项。
